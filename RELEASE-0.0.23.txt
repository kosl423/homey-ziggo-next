Ziggo Next for Homey v0.0.23
Improved power control and reduced installation size
Released: October 23, 2026

CHANGES
- Centralized power control for standard Homey on/off commands and the Power button.
- Concurrent requests for the same state share a single transition. Conflicting
  requests use the latest requested state.
- Outdated commands can be cancelled before transmission.
- Power commands are not automatically retried after a timeout, connection loss,
  or restart when the outcome of a previous command is uncertain.
- Early MQTT status messages are buffered and processed in order before pending
  power requests are evaluated.
- On/off requests wait up to 10 seconds for an initial live status. Expired
  requests are cancelled and will not execute later.
- Device warnings indicate when the power state has not been confirmed.
- Expanded power diagnostics with serialized storage and a 250-entry limit.
- Significantly reduced installation size by excluding development tools from
  production dependencies.

COMPATIBILITY AND VALIDATION
- Homey Pro with Homey software 10.0.0 or later.
- App ID, driver ID, capabilities, and Flow card definitions are unchanged.
- Production dependency versions are unchanged from v0.0.22.
- 56 automated offline tests passed.
- v0.0.22 remains available through its existing version tag.

KNOWN LIMITATIONS
- Power control requires a valid live status after startup or reconnection.
  Retained status messages alone do not enable power commands.
- An uncertain command outcome may require a new live status before further
  power commands can be accepted.
- MQTT key commands continue to use QoS 2 and retain=true. This does not guarantee
  exactly one physical execution across the complete Ziggo service chain.
- Power-state updates do not identify what caused the device to switch on.
- Pairing and Repair require exactly one assigned Mediabox.
- Cleared diagnostic entries may reappear when a subsequent message is logged.
